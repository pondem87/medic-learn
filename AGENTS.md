# Instructions for coding agents

Read [ARCHITECTURE.md](ARCHITECTURE.md), [STYLE_GUIDE.md](STYLE_GUIDE.md),
[CONTRIBUTING.md](CONTRIBUTING.md), and the profiles selected in the project README.
Follow nested instructions, including [docs/AGENTS.md](docs/AGENTS.md), where applicable.
Inspect relevant requirements, ADRs, code, callers, tests, and Git changes first.

This scaffold contains documentation only. Apply component rules only to components
that exist or are being introduced. Examples and blank templates do not establish
business requirements. Preserve shared architecture while using idiomatic language
profiles. Record material departures explicitly in a project ADR.

Complete authorized work, preserve unrelated changes, and resolve discoverable
questions from repository evidence. Ask about unresolved business rules that
materially affect behavior. Keep implementation, tests, and documentation aligned.
Do not introduce infrastructure merely to satisfy a checklist.

Use the contribution checks appropriate to the change. For prose changes validate
links, examples, and consistency; do not claim builds or tests ran in a documentation
starter. Review the final diff and report actual validation and unresolved issues.
Keep credentials, generated data, and sensitive information out of changes.
